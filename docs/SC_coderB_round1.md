## 4. 为什么这么低：两个性质不同的原因

**(a) 判定规则理解不一致（可通过修订手册解决）**

- `c3 Concrete`：交回方 13/13 全判 1，说明凡出现「法官」「东北」「日本」「美国」「煎锅」一类具体词都算；
  coderA 只把**具体案例/人名/地名/产品名/机构名/案件名**算数，泛指角色不算。codebook 虽有「泛指的『某公司』不算」，但没说清国名、物品名、泛指职业该如何归类。
- `st3 Stories`：交回方 7/13 判 1，把设问式标题、事件描述当成叙事；coderA 严格执行「人物 + 障碍 + 结局」三者齐全，故全 0。
- `e4 Emotional`：交回方 7/12 判 1，把「强硬反制！」「智商税还是高科技」等表态/设问视为情绪唤起；coderA 只在明确煽情时判 1。
- `u3 Unexpected`：交回方把单个数字或普通反差算作「数量级反差」，与规则项 `u2`（疑问句）边界混淆。

**(b) 常量边际让 kappa 结构性不可估计（不是"吵得凶"那么简单）**

coderA 的 `s1` 全为 1、`u3` 与 `st3` 全为 0；交回方的 `c3` 全为 1。
当一方的边际分布完全集中在一个类别时，`po = pe`，**kappa 恒等于 0**，哪怕两人几乎全部同意。
所以这四个 `0.000` 同时说明：① 13 条样本里这些维度本身缺乏变异；② coderA 的判定尺度可能过严/过宽。
这与主样本里 `s_credible` / `s_stories` 变异稀疏是同一个问题的两端。

## 5. 按预注册该怎么走

`docs/codebook.md` 与 `docs/SC_preregistration.md` 已写明：**kappa < 0.70 → 回 codebook 修订判定细则 → 重新培训 → 重编 → 记录修订过程**。
低信度是研究设计素养的体现，不是需要掩盖的缺陷，更不是回头改假设或调词典的理由。

建议的 v0.3 修订点（每条都必须配正例 + 反例，且在**看到回归结果之前**冻结）：

| 指标 | 需补的规则 |
|---|---|
| `c3` | 明确国名 / 物品名 / 泛指职业是否算「具体」；给「某公司」「法官」「煎锅」「美国」逐项判例 |
| `st3` | 明确「设问式标题 ≠ 叙事」；人物、障碍、结局三者缺一不可；给一个判 1 的完整叙事例句 |
| `e4` | 给「中性科普 / 新闻表态 / 明确煽情」三级对照例句，划清与规则项 `e1` 的边界 |
| `u3` | 明确必须**同一文本内两组数量级数字**；单个数字、普通疑问句归 `u2`，不算 `u3` |
| `s1` | 补 2–3 个并列话题反例，校准 coderA 全判 1 是否过宽 |

另建议把双编码样本扩到 **≥30 条**（现 13 条 CI 过宽，且常量边际更易出现）。
