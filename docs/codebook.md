## 通用规则

- **编码单元**：一条视频 = 一行。编码素材为 `title` + `desc`（简介）；若取得字幕，另加 `intro`（前 30 秒口播）。
- **记分**：每条指标为 0/1（出现=1）；每维得分 = 该维指标均值，范围 0-1。
- **标注方式**：`R/` 脚本用词典 + 正则做规则标注（可复现）；`Stories` 与 `Simple` 的语义判断用人工复核。
- **一致性检验**：随机抽 20% 样本由第二人独立编码，报告 **Cohen's kappa**，目标 ≥ 0.70；低于则修订规则重编。这一条务必写进报告。
- **盲法**：编码时屏蔽播放/点赞等结果变量，避免"看到爆款就觉得它更 Simple"的后见之明偏差。

## S — Simple 简约

> 构念：信息聚焦、易被记住。不是"内容浅"，而是"核心主张单一"。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| S1 | 标题只传达一个核心主张，无并列主题（不含 "和/与/以及/、" 连接的两个话题） | 人工 0/1 |
| S2 | 标题字数 ≤ 20 字 | 规则 |
| S3 | 含"一句话结论"标记：`一句话` `搞懂` `讲清` `其实就` `只需` `3分钟` `本质上是` | 规则 |
| S4 | 抽象术语密度低（词典：`底层逻辑` `方法论` `认知` `范式` `维度` `体系` 出现 0 次） | 规则 |

**示例**：「为什么手机越充越慢？其实就是这一个元件」→ S1=1, S2=1, S3=1, S4=1。

## U — Unexpected 意外

> 构念：打破预期、制造信息缺口。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| U1 | 反预期结构：`你以为` `其实不是` `并不是` `错了` `恰恰相反` `颠覆` `真相是` | 规则 |
| U2 | 疑问句或悬念：含 `?`/`？`/`为什么`/`到底`/`竟然`/`凭什么` | 规则 |
| U3 | 数字反差或冲突并置：一段文本内出现两组数量级差异明显的数字，或 `A 和 B 的差距` 类结构 | 人工 0/1 |
| U4 | （可选，需字幕）开场先抛问题、30 秒后才给答案 | 人工 0/1 |

## C — Concrete 具体

> 构念：可感知、可想象的对象，而非抽象概念。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| C1 | 标题或简介含阿拉伯数字（具体量） | 规则 |
| C2 | 含可感知实体/场景名词：钱、工资、手机、地铁、一天、10 分钟、一杯、一张…（词典维护在 `R/02_code_succes.R`） | 规则 |
| C3 | 含具体案例、人名、地名、产品名或机构名 | 人工 0/1 |
| C4 | **v0.2**：含「数字 + 具体单位」的可感知量化短语（正则 `[0-9]+ ?(元|块|年|个月|天|小时|分钟|公里|人|%|次|倍|万|亿|岁…)`） | 规则 |

## Cr — Credible 可信

> 构念：让人相信，靠可核验的外部依据而非自述权威。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| Cr1 | 简介注明数据来源 / 论文 / 机构 / 报告名 | 人工 0/1 |
| Cr2 | 出现 `研究显示` `实验` `数据` `调查` `论文` `根据` `统计` 等依据词 | 规则 |
| Cr3 | 含可点击出处（链接、DOI、参考文献列表） | 规则 |
| Cr4 | UP 主具平台官方认证或可核验专业身份（取接口 `official` 字段） | 规则 |

**注意**：Cr4 是账号属性而非内容属性，稳健性检验里要单独剔除它重跑一次。

## E — Emotional 情感

> 构念：唤起情绪以促进行动。按 H5，预设与互动率正相关；若未获支持，按预注册口径如实报告效应量与置信区间，不事后修改假设方向。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| E1 | 标题含情绪唤起词：`震惊` `崩溃` `后悔` `焦虑` `扎心` `救命` `细思极恐` `爽` `绝了` | 规则 |
| E2 | 使用第二人称 `你` / `你的` / `千万别` | 规则 |
| E3 | 损失或收益框架：`别再` `错过` `省下` `避免` `少走弯路` `白花` | 规则 |
| E4 | **v0.2 人工**：标题/简介是否含明确情绪唤起意图（非中性陈述），由编码员判断 0/1 | 人工 0/1 |

## St — Stories 故事

> 构念：以叙事推动理解。这是最难靠标题代理的一维，**必须在局限里明确说明**。

| 指标 | 判定规则 | 类型 |
|---|---|---|
| St1 | 以人物经历或具体案例开场：`我朋友` `有个学生` `曾经` `我当年` `某位` | 规则 |
| St2 | 含叙事时序标记：`先` `后来` `结果` `直到` `没想到` | 规则 |
| St3 | 困境—转折结构（人工判定：出现人物 + 障碍 + 结局） | 人工 0/1 |
| St4 | 时长 ≥ 8 分钟且简介含案例段落（弱代理，单独标注 `st_weak=1`） | 规则 |

## 六个人工语义指标：判定细则（v0.2，双人编码必读）

编码素材只有 `title` + `desc` + `intro`（字幕覆盖率 0%，`intro` 实际为空）。
**盲法**：编码时不得查看 `view` / `like` / `engage_rate` / 榜单排名，编码表已剔除这些列。
每条指标填 `0` / `1`；判不准填 `9` 并在 `note` 列写一句理由，不要猜。

| 指标 | 维度 | 判 1 的条件 | 判 0 的条件 | 易错点 |
|---|---|---|---|---|
| `s1` | Simple | 标题只传达**一个**核心主张，可用一句话复述 | 出现两个并列话题（"A 和 B""A、B、C"）、或标题是开放式罗列 | 长标题不等于多主张；有副标题但主句单一仍判 1 |
| `u3` | Unexpected | 同一文本内出现**数量级明显不同的两组数字**，或 A/B 冲突并置（"X 赢了，其实输了"） | 只有单个数字、或只是普通疑问句 | 疑问句由规则项 `u2` 负责，`u3` 只判「反差/冲突」，不要重复计 |
| `c3` | Concrete | 出现具体案例、真实人名、地名、产品名、机构名或案件名 | 只有抽象概念（"社会""制度""心理"） | 国名/机构名算具体；泛指的"某公司""一个人"不算 |
| `cr1` | Credible | 简介**明确注明**数据来源 / 论文 / 报告名 / 机构署名 | 只写"据说""有研究表明"而无出处、或完全没提 | 与规则项 `cr2`（依据词）不同：有"数据"二字但无出处仍判 0 |
| `st3` | Stories | 出现**人物 + 障碍 + 结局**的困境—转折结构 | 纯说明、纯论点罗列、纯清单 | 标题讲一个事件不等于叙事；必须有人物与转折 |
| `e4` | Emotional (v0.2) | 标题/简介有**明确的情绪唤起意图**（愤怒、震惊、同情、焦虑、爽感等），非中性陈述 | 客观陈述、平铺直叙的科普或新闻 | 与规则项 `e1`（情绪词）互补：有情绪词但整体中性，可判 0；无词典词但明显煽情，可判 1 |

## v0.3 判定细则补订（2026-11-06，第一轮双人编码后）

> **触发**：第一轮 20% 双编码（n=13）六指标一致性全部低于 0.70，且 `s1/u3/st3`（coderA）与 `c3`（coderB）
> 出现常量边际，使 kappa 结构性不可估计。诊断与逐格分歧见 `docs/SC_coderB_round1.md`。
> **性质**：这是**判定细则**修订，不是改假设、不是调词典、不是看结果找故事；修订发生在
> 看到评分者信度诊断之后、**看到任何回归/假设检验结果之前**（主模型至今未运行），已登记为预注册变更 E。
>
> ⚠️ **下列例句全部为虚构，不来自本项目 13 条样本**。手册不得反推或暗示任何具体视频的「正确答案」，
> 否则第二轮编码将不再是独立编码。两位编码人只依据标题 + 简介独立判断。

### `c3` Concrete —— 只判「专有名词 / 具体案例」

| 情形 | 判定 | 例（虚构） |
|---|---|---|
| 真实人名、机构名、产品名、期刊名、案件名、国名/地名 | **1** | 「罗翔」「马斯克」「王者荣耀」「母子健康」「美国」「青藏高原」 |
| 泛指类别、职业、角色、群称 | **0** | 「法官」「原配」「人类」「某公司」「一个人」「隔壁案」 |
| 普通物品名、可感知场景名词 | **0** | 「煎锅」「冰块」「手机」「一杯水」——已由规则项 `c2` 负责，`c3` 不重复计 |
| 抽象概念 | **0** | 「社会」「制度」「心理」「物理学」 |

**边界裁定**：「虚假亲子鉴定机构」是**类别**而非具体机构名 → 0；「孙建琴」（文献作者）是具体人名 → 1。
判定口径一句话：**能不能在地图上、名单里或工商登记里指到那一个？能 → 1，只能指到一类 → 0。**

### `st3` Stories —— 人物 + 障碍 + 结局，三者缺一不可

- **判 1**：文本里能找出 (a) 一个明确人物／拟人主角，(b) 他遇到的障碍或困境，(c) 转折或结局。
  例（虚构）：「我朋友考研三战失败，后来去做了木匠，现在反而活得松弛」→ 1。
- **判 0**：设问式标题、假设前提、事件罗列、活动介绍、纯说明、纯清单。
  例（虚构）：「开一家店要办哪些手续？」→ 0；「某机构推出了一系列公益皮肤」→ 0。
- **易错点**：标题讲了一个**事件**不等于叙事；「先／后来／结果」等时序词只是规则项 `st2` 的信号，
  单独出现不能判 `st3=1`；「我当年…」式的单一回忆片段若没有障碍与结局，仍判 0。

### `e4` Emotional —— 判「意图」，不判「话题是否带情绪色彩」

| 层级 | 判定 | 例（虚构） |
|---|---|---|
| 纯信息设问、事实陈述、实用指导、新闻事实（即使带感叹号） | **0** | 「再加征 50% 关税」「必看避坑指南」「A 和 B 有什么区别？」 |
| 轻微感受、戏谑措辞，但整体是中立信息包装 | **0** | 「听起来挺烧心」「看似简单，其实另有门道」 |
| 明确的情绪唤起：直接情绪词、吐槽／诉苦语气、诉诸第二人称的煽动 | **1** | 「疯批冷空气要来了，能不能别搞我们啊」「千万别再踩这个坑了」 |

**与规则项的关系**：`e1` 管词典里的情绪词，`e4` 管整体意图 —— 有情绪词但整体中性可判 0，
无词典词但明显煽情可判 1。**疑问、反差、悬念制造的是信息缺口（U 维度），不是情绪**；
「智商税还是高科技」这类中性设问判 0。判不准填 `9` 并写理由，不要靠猜。

### `u3` Unexpected —— 只判「数量级反差 / 冲突并置」

- **判 1**：同一段文本内出现**两组数量级明显不同的数字**，或 A/B 结果冲突并置。
  例（虚构）：「判了 3 年，隔壁案只判 3 个月」→ 1；「100 元和 1 元的矿泉水」→ 1。
- **判 0**：只有一个数字（「50%」「200 万美元」「3 种方法」）、同一集合内的数量（「三个小球」）、
  量级相近的数字（「十几度 / 二十度」）、纯疑问句或悬念。
- **不要重复计**：疑问句与悬念归规则项 `u2`；`u3` 不是「看起来意外」的笼统判断。

### `s1` Simple —— 并列结构必须判 0

- **判 1**：整条标题能用一句话复述一个核心主张；副标题、补充限定不改变主句单一性。
  例（虚构）：「为什么手机越充越慢？其实就是这一个元件」→ 1；「A 和 B 的差距」→ 1（单一比较主张）。
- **判 0**：两个及以上并列话题、开放式罗列、**多个并列设问**。
  例（虚构）：「为什么年轻人不买房，以及房价未来会怎么走？」→ 0；
  「职场沟通、时间管理与情绪控制」→ 0。
- **自检**：若整批样本里某指标判 1 的比例接近 100%，先回看本条反例复核尺度，
  而不是默认全填 1 —— 常量边际会让 kappa 无法估计，即使两人完全一致也算不出信度。

### `cr1` Credible —— 保持 v0.2 口径不变

简介**明确注明**数据来源／论文／报告名／机构署名 → 1；只写「据说」「有研究表明」或
出现「数据」二字但无出处 → 0。第一轮该指标是唯一 kappa > 0 的项，规则不动，
只在第二轮扩大样本量以收窄置信区间。

### 第二轮编码的校准流程（新增）

1. 两位编码人各自先通读本 v0.3 补订，再**独立**试编 3 条虚构校准例句；
2. 校准阶段允许讨论**规则表述**是否清楚，并把歧义写回本手册（记为 v0.3 修订留痕）；
3. 进入正式 13 条编码后，两人**不得交流任何一条的判定**、不得查播放/点赞数据、不得看对方表格；
4. 判不准填 `9` 并在 `note` 写一句理由；`9` 会作为独立类别计入 kappa。

**双人编码流程（v0.3 · 第二轮，A / B 双份盲法）**

> 第一轮（coderA 由脚本代填 + coderB 真人）信度未达标，按变更 E 重编。**两位真人都按 v0.3 重编同一 13 条**。

1. `data/processed/SC_manual_coding.csv` 是 64 行主编码表；`SC_double_coding_template.csv`
   是 13 条双编码汇总表。两者都含**已填的编码结果与判定理由**，**一律不得直接发给任何编码人**；
2. `python3 SC_export_coderB.py --role A` 与 `--role B` 分别生成
   `data/processed/handoff/round2/SC_round2_coderA_sheet.xlsx` / `..._coderB_sheet.xlsx`
   （两个 sheet：填写说明 + 编码表；只含 `bvid/title/desc/intro` 与 6 个空白待填列，
   带 `0/1/9` 下拉校验；说明页为 v0.3 细则；导出脚本自带泄露自检）。同目录另有 CSV、说明 md 与 zip；
3. 两位**真人**各拿一份、独立填写，互不可见对方答案、不查播放/点赞数据、不与对方讨论具体条目；
   判不准填 `9` 并写理由；
4. 交回后分别运行
   `python3 SC_import_coderB.py <交回文件> --role A` / `--role B`（可先加 `--dry-run`）：
   校验 bvid 集合、素材未被改动、78 格值域与完整性、coder_id，通过后合并回主模板
   （写入前自动备份；只写本角色对应的 `*_coderA` 或 `*_coderB` 列，另一方的答案与
   `coded_date` / `note` 一律不覆盖，本角色的日期与备注写 `coder{A,B}_date` / `note_coder{A,B}`）；
5. 两份都导入后运行 `Rscript R/SC_kappa.R`，逐指标输出 Cohen's kappa 与 bootstrap CI；
6. 若仍有 kappa < 0.70 → 回到本表修订规则、重编，并在报告「编码一致性」一节写明修订过程；
   若出现常量边际（`po=pe`），先检查判定尺度是否过严/过宽，必要时扩大双编码样本到 ≥30 条。

> **诚实边界（v0.3 收紧）**：第二轮起 **A、B 两份编码都必须由真实的人独立产生**。
> 第一轮 coderA 由脚本代填（`assistant-coderA-demo`）只作流程演示，不构成「两位真人」的信度证据，
> 其数据已归档弃用。脚本附带的「模拟双编码」只用于验证公式，其数值不得当作一致性证据写进报告或对外表述。
> 交付包里刻意不含对方答案、判定理由与结果变量（播放/点赞/排名），说明页明确要求不查视频数据、不与对方讨论。

## 编码表字段（骨架阶段设计）

> 下表是**最初骨架阶段的字段清单**。本轮实际表头以 `data/processed/SC_mvp_coded.csv`

## 常见坑

1. **六维不是独立的**：`Concrete` 与 `Simple`、`Unexpected` 与 `Emotional` 往往相关，报告 VIF，别逐个单独下结论。
2. **不要事后改规则**：看到结果不显著就加词进词典 = p-hacking。词典版本冻结后写进报告，改动需留 changelog。
3. **人工指标要留痕**：`coder_id` 与 `coded_date` 必填，方便复现与一致性检验。
4. **标题不等于内容**：本项目测的是"包装特征"，不是"内容质量"。这句话要原样写进报告摘要。
5. **不要复用同一列当两个指标**：v0.1 的 `s4` 与 `c4` 完全相同，曾人为制造两维耦合；任何新指标都必须先检查与既有列的相关是否为 1。
6. **字幕为 0 时不要假装测到了 Stories**：`u4` 标 NA，`st3` 靠人工，`st4` 保留 `st_weak=1`，并在报告里写明该维效度受限。
