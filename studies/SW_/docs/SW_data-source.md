> 核查日期：2026-11-07 ｜ 所有结论来自实际下载解压与真实接口请求，不是推测。

## 1. 视频元数据：Kaggle「每周必看」

| 项 | 值 |
|---|---|
| 引用 | `zhuosun03/bilibili-must-watch` |
| 文件 | `B_231009_1696842727.csv`（UTF-8 BOM，2,121 KB） |
| 规模 | 8,104 行 / **8,064 唯一 bvid** / 237 期 |
| 时间 | 发布时间 2019–2023；期数描述 `2019第1期 03.22-03.28` ~ `2023第237期 09.29-10.05` |
| **许可** | Kaggle `licenseName` = **Unknown** |
| 下载 | 公开端点 `https://www.kaggle.com/api/v1/datasets/download/<ref>`，HTTP 200，**免登录、无 token** |
| 完整性 | sha-256 见 `data/external/SW_download_manifest.csv` |

**许可处理**：由于许可不明，原始 CSV / zip **不随仓库分发**，`.gitignore` 已排除；仓库只保留下载脚本、manifest、样本框（bvid 与公开元数据）与聚合结果。若日后要公开仓库，需先向上传者确认许可或仅发布聚合统计。

**全部 18 列**：`期数 / 期数描述 / 标题 / 视频类型 / 视频标签 / 视频链接 / 视频时长 / up主 / up主_id / aid / 投币数 / 弹幕数 / 收藏数 / 点赞数 / 评论数 / 分享数 / 播放数 / 发布时间`。

### 字段语义核查（两个容易踩的坑）

1. **`视频标签` 不是标签**。抽样 8 条与全量统计显示：中位长度 11 字、最长 40 字、多数是完整句子
   （例：「一支视频告诉你消防员的身体素质到底有多强」「盛世中华，山河秀丽，永远昌盛」），
   实为**每周必看榜单一句话推荐语**。本项目把它作为 `blurb`（代替 `SK_` 项目的 `desc`）输入编码表，
   并在预注册 SW-变更 A 登记：内容更短，依赖长文本的规则项命中率会系统性偏低，**不加词补偿**。
2. **没有评论正文**。只有 `评论数`（计数）、`弹幕数`（计数）。评论正文必须另行采集。

**bvid 与 aid**：`视频链接` 形如 `https://b23.tv/BV16b411b71j`，正则 `BV[0-9A-Za-z]{10}`
可 100% 提取（8,104/8,104）。数据集自带 `aid`；评论接口需要 `oid=aid`。
抽样 20 个 bvid 调公开 `x/web-interface/view?bvid=` 核验：
**18 个一致、0 个不一致、2 个返回 `-404`（视频已不可见）**，明细见 `output/SW_bvid_aid_check.csv`。
主流程以 **bvid 为唯一主键**，`aid` 取自数据集并已抽样验证，避免为每个视频多发一次请求。

## 2. 评论：B 站公开接口

| 项 | 值 |
|---|---|
| 端点 | `GET https://api.bilibili.com/x/v2/reply?type=1&oid=<aid>&sort=2&pn=1&ps=20` |
| 认证 | 无 Cookie、无 token、无 WBI 签名；普通浏览器 UA + Referer |
| 限速 | 固定 1.1 秒/请求 |
| 返回 | `data.replies` = **3 条热评**（按热度），`data.top_replies` = 1 条置顶（常与热评重复） |
| 保存字段 | `bvid / aid / split / rank / rpid / like / ctime / message`（公开评论 ID 与正文） |
| **不保存** | 用户名、`mid`、头像、签名、IP、等级、会员信息等任何身份字段 |

**评论正文的再分发与脱敏**：评论原文可能含公开 `@提及`（实测 1,454 条中 2 条）与链接（23 条）。
这些文本属于用户生成内容，因此原始评论表与逐行分析表**一律不提交仓库**（见 `.gitignore`），
只保留聚合结果；编码时 `SW_info_markers.clean()` 统一去除 URL 与表情码 `[xxx]`，
`@提及` 不参与任何规则项匹配。全量扫描未发现手机号、微信号、QQ 号或邮箱。

### 实测的接口边界（不绕过）

| 尝试 | 结果 |
|---|---|
| `sort=2 / sort=1, pn=1, ps=20` | `code=0`，`replies` **恒为 3 条**，尽管 `page.count` 数千 |
| `sort=2, pn=2` | `code=0` 但 `page` 全 0、`replies` 空 |
| `sort=0, pn=1` | `code=0` 但 `replies` 空 |
| `nohot=1` | 与不传相同，仍 3 条 |
| `x/v2/reply/main?mode=2 / mode=3` | **`code=-352`**（WBI 风控）→ 直接放弃，不签名、不绕过 |
| `x/v2/reply/reply?root=<rpid>` | `code=0`，可取 20 条楼中楼，但点赞普遍个位数，**不是高赞评论**，本项目不采用 |
| `code=12002` | 「当前页面评论功能已关闭」，只记录、不重试 |

> **因此每个 bvid 只能拿到 3 条高赞评论，不是需求初始设想的 10 条。**
> 这是未登录公开接口的限制；本项目选择如实记录，而不是用楼中楼或伪造排序凑数，
> 也不尝试登录、WBI 签名、换 IP 或任何频控规避。

## 4. 已知限制（写进任何结论）

1. **许可 Unknown**：原始 CSV 不分发，二次使用需自行确认权利。
2. **时间错位**：视频发布于 2019–2023，评论抓取于 2026-11-07；热评是长期累计后的当日快照，不能解释为发布当时的观众反应。
3. **选择偏差**：每周必看本身是平台精选榜单；高赞热评又被点赞机制筛过，多为神评论/玩梗/共鸣，**不代表全体观众、也不代表全部评论**。
4. **测量天花板**：`dev` 集 180 条高赞评论里「学到了/感谢科普/涨知识/受益匪浅/记笔记」**0 命中**，
   「明白了/懂了/才知道」3 条命中经逐条核对均为叙事误报。因此「观众获取信息」的显性表述**不可测**，
   主因变量改为可复现的「信息性讨论」（详见 `docs/SW_preregistration.md` 第 1 节与 `SW_report.md`）。
5. **接口失败**：评论关闭等 `code!=0` 的视频自然缺失，实际 N 以 `output/SW_data_health.txt` 为准。
6. **无曝光分母**：评论层面的「谁看过但没评论」不可观测，不能计算真实获取率。
